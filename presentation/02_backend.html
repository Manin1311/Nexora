Backend — Django Architecture

⚙️ Backend Deep Dive

Django 5.1 + Django REST Framework + Django Channels — a production-grade ASGI backend serving REST APIs and real-time WebSockets, powered by dual AI engines with automatic failover.

Backend Technology Stack

📦 Core Framework Dependencies

django>=5.1 Web framework — ORM, Auth, Admin
djangorestframework>=3.15 REST API views & serializers
simplejwt>=5.3 JWT access + refresh token auth
django-cors-headers>=4.3 Cross-origin requests (Frontend↔API)
channels>=4.1 + daphne>=4.1 ASGI server for WebSockets

gunicorn + whitenoise WSGI server + static files
pypdf + Pillow PDF parsing & image processing

🏗️ Why This Stack?

  • Django ORM — Pythonic, readable queries. Custom AbstractBaseUser model for email-based auth.
  • DRF Serializers — Auto-validate request data, serialize querysets to JSON. Reduces boilerplate by 80%.
  • SimpleJWT — Stateless authentication. Access tokens (5 min) + refresh tokens (7 days) — no session storage needed.
  • Django Channels + Daphne — Upgrades Django from WSGI (HTTP-only) to ASGI, enabling WebSocket connections for real-time Code Arena battles.
  • Groq API — LLaMA 3.3 70B inference is ~10x faster than OpenAI GPT-4 at lower cost. Critical for real-time interview feedback.
  • Gemini Multimodal — Only Gemini supports image + text in a single API call, needed for webcam frame analysis during interviews.
  • PostgreSQL — ACID compliant, supports JSONField natively (used extensively for AI memory, resume data, roadmap tasks).

Key Files — Detailed Explanation
core/gemini_client.py 🧠 Central AI Brain — 1770 lines
  • This is the most critical file in the backend. ALL AI interactions from ALL 12 apps go through this single module.
  • _call_groq(prompt, system, temperature) — Primary AI caller. Sends prompt to Groq's LLaMA 3.3 70B. Has multi-key rotation: tries each Groq API key in random order to distribute load. On 429 rate limit → waits and retries. If ALL keys fail → auto-calls _call_gemini_fallback().
  • _call_gemini_fallback(prompt, image_frame) — Google Gemini fallback. Supports multimodal input: if an image_frame (base64 webcam snapshot) is provided, it sends the image WITH the text prompt to Gemini Vision for posture/eye-contact analysis.
  • evaluate_challenge_submission() — Evaluates code answers. Returns JSON with score (0-100), strengths, improvements, time/space complexity in Big-O notation, and a markdown complexity table. Has a smart local heuristic fallback if AI fails.
  • generate_interview_questions(mode, difficulty, topic, count, resume_context) — Generates personalized interview questions. If user has a resume, builds a context block with their skills, projects, and experience so AI asks questions about THEIR actual work.
  • evaluate_interview_answer(question, answer, image_frame) — Evaluates interview answers. Sends webcam snapshot to Gemini Vision for body language analysis alongside the text answer.
  • generate_boardroom_debate() — Special multi-panelist mode. AI generates responses from 3 simultaneous panelists: Tech Lead, Architect, and HR Manager, each with different perspectives on the answer.
  • generate_roadmap(user_data, target_role) — Creates week-by-week learning paths personalized to user's skill gaps.
  • analyze_github_repo() — Fetches repo file tree via GitHub API, reads source code, and generates a structured issue report with severity levels (Critical/High/Medium/Low).
  • generate_ats_analysis() — Takes resume JSON + target role, generates ATS score (0-100) with keyword gaps, strengths, checklist items.
users/models.py 👤 User System — 157 lines
  • Custom User Model — Extends AbstractBaseUser + PermissionsMixin. Uses email as USERNAME_FIELD (not username). Django's default username-based auth is replaced with email-based. UserManager handles create_user() and create_superuser().
  • UserProfile — One-to-one with User. Stores: bio, avatar image, dev_rank (Explorer/Builder/Creator/Architect/Legend), total_xp, streak_days, GitHub integration fields (username, repos JSON, code health score). update_rank() method auto-upgrades rank based on XP thresholds.
  • Resume — One-to-one with User. Stores 6 JSON sections: personal_info, experience, projects, skills, education, certifications. Also stores ats_score, audit_report (JSON), and target_role.
  • UserAIMemory — One-to-one with User. The AI Memory Engine. Stores: skills_mastery (dict), strengths (list), weaknesses (list), recurring_mistakes (list), interview_stats (dict), career_goals (dict), activity_log (list). AI reads this before every response to personalize output.
  • Notification — User notifications with read/unread status. Created automatically when XP is awarded, rank changes, or achievements are earned.
challenges/views.py 🎯 Challenge API — 702 lines
  • ChallengeListView — Supports query params: ?difficulty=easy&type=daily&topic=5&search=array. Uses Django ORM filter() chains with Q() objects for multi-condition filtering.
  • SubmitChallengeView — Handles challenge submission. Creates ChallengeSubmission, calls evaluate_challenge_submission() from AI client, saves score/feedback/complexity data, calls award_xp() with XP multiplier from AI evaluation, creates notification.
  • OA Simulation Mode — oa_challenges.py contains company-specific assessment scenarios (Google, Amazon, etc.) with multi-step problem sets, time limits, and anti-cheat telemetry logging via AssessmentTelemetry.
  • GenerateAIChallengeView — User can request an AI-generated challenge for any topic. AI generates question, requirements, difficulty, and XP reward dynamically. No pre-seeded challenge needed.
interviews/views.py 🎤 Interview Session API — 207 lines
  • StartInterviewView (POST) — Creates InterviewSession, optionally loads user's Resume for personalized questions, calls generate_interview_questions(mode, difficulty, topic, count, resume_context). Creates N InterviewQuestion objects with the AI-generated questions.
  • SubmitAnswerView (POST) — Receives: answer (text), image_frame (base64 webcam JPEG), filler_words_count, speaking_pace (WPM). Calls AI to evaluate answer with behavioral metrics. Special Boardroom mode generates multi-panelist debate response.
  • CompleteInterviewView (POST) — Calculates average score across all questions, awards XP, updates AI Memory with interview performance, logs activity, marks session as completed.
arena/consumers.py ⚡ WebSocket Consumer — 437 lines
  • Inherits from AsyncWebsocketConsumer (Django Channels). Uses async/await — non-blocking, handles many concurrent connections without threads.
  • connect() — Authenticates user via JWT in WebSocket scope, gets/creates room from ROOMS dict (in-memory room state), joins channel layer group (arena_{room_code}). Closes with code 4001 (unauthenticated), 4004 (room not found), or 4003 (finished).
  • receive() — Handles 3 message types from client: progress_update (player solved X tests), battle_finish (all tests passed — declare winner), ping (keepalive heartbeat).
  • Battle broadcast — Uses channel_layer.group_send() to broadcast events to BOTH players simultaneously: room_state, player_joined, battle_start, progress_update, battle_finish, player_left.
  • Room state is held in module-level ROOMS dict (backed by room_manager.py), not in database — for ultra-fast real-time reads without DB queries during battle.
progress/utils.py 🏆 XP & Gamification Engine
  • award_xp(user, amount, reason) — Called from every module (challenges, interviews, arena). Adds XP to UserProfile.total_xp, calls update_rank() to check for rank-up, creates a Notification if rank changes, logs UserActivity.
  • log_activity(user, type, description, xp, metadata) — Appends to UserActivity table AND updates UserAIMemory.activity_log JSON array so AI knows what user has been doing across sessions.
  • award_certificate(user, challenge) — Generates a Certificate with a unique UUID-based certificate_id for completing hard challenges. Shareable verification link.

API Request Lifecycle — Challenge Submission Example
1

Frontend sends POST /api/challenges/42/submit/

Axios sends { content: "def solution(n): return n*(n+1)//2" } with Authorization: Bearer <access_token> header

2

SimpleJWT Middleware authenticates token

Decodes JWT → gets user ID → attaches request.user object. Rejects with 401 if token expired or invalid.

3

SubmitChallengeView.post() runs

Fetches Challenge from DB, checks if already submitted (unique_together constraint), gets or creates ChallengeSubmission, calls AI evaluator.

4

evaluate_challenge_submission() in core/gemini_client.py

Builds prompt with challenge title + description + user answer → sends to Groq LLaMA 3.3 70B → gets JSON response with score, feedback, complexity. Strips markdown fences, parses JSON.

5

Saves result, awards XP, creates notification

Saves score/feedback/complexity to DB. Calls award_xp(user, xp_reward * xp_multiplier). Creates XP notification. Calls log_activity() to update AI Memory.

6

Returns serialized response to frontend

DRF serializes ChallengeSubmission to JSON → 200 OK response. Frontend displays score, feedback, complexity chart, XP earned.

Authentication System — JWT Flow

🔐 How JWT Authentication Works in Nexora

User logs in → backend verifies password → returns access token (expires in 5 minutes) + refresh token (expires in 7 days). Frontend stores both in localStorage. Every API request sends Authorization: Bearer <access_token>. When access token expires, frontend auto-sends refresh token to /api/auth/token/refresh/ to get a new access token — user never sees a logout. SimpleJWT handles all token crypto (HS256 signing) automatically.

⚠️ Custom User Model Design Decision

Django's default auth uses username as the login field. Nexora replaces it with email (USERNAME_FIELD = 'email') using a custom AbstractBaseUser. This must be done BEFORE the first migration — it cannot be changed mid-project without data migration headaches. We planned this from day one.
