AI Layer — Groq + Gemini

🤖 AI Layer Deep Dive

Nexora's AI backbone: Groq LLaMA 3.3 70B as primary engine + Google Gemini 2.5 Flash as multimodal fallback. Multi-key load balancing, automatic failover, and 1770 lines of carefully engineered AI functions powering every feature.

Dual AI Engine Architecture
⚡
Groq — LLaMA 3.3 70B (Primary)
Groq Cloud Inference API · groq>=0.9.0
  • Speed: Groq's custom LPU (Language Processing Unit) hardware delivers 500+ tokens/sec — ~10x faster than OpenAI GPT-4
  • Model: LLaMA 3.3 70B by Meta — open source, 70 billion parameters, excellent at code and reasoning
  • Usage: All text-only AI tasks: challenge evaluation, interview Q generation, roadmap creation, ATS analysis, mentor chat, peer review analysis
  • Multi-key: Multiple Groq API keys configured. Random starting key per request. Rate limit (429) → wait + retry → next key
  • Max tokens: 2048 per response (configurable per function)
  • JSON mode: response_format: {"type": "json_object"} forces structured JSON output without markdown fences
Primary EngineText + CodeMulti-key
🧠
Google Gemini 2.5 Flash (Fallback + Vision)
Google Generative AI SDK · google-generativeai>=0.8
  • Trigger: Auto-activated when ALL Groq keys are rate-limited or fail
  • Multimodal: ONLY Gemini supports image + text in a single API call. Used for webcam frame analysis during interviews
  • Models tried in order: gemini-2.5-flash → gemini-2.0-flash → gemini-1.5-flash → gemini-1.5-pro
  • Multi-key: Multiple Gemini API keys. Random starting key. Tries all key × model combinations
  • Image analysis: Base64 JPEG webcam frames decoded, sent with prompt for posture, eye contact, facial expression analysis
  • System instruction: Role-based system prompts set AI persona per function (senior dev, interview coach, career advisor)
Fallback EngineMultimodal VisionAuto-switch

🛡️ Local Heuristic Fallback (Last Resort)

If BOTH Groq AND Gemini completely fail, critical functions like evaluate_challenge_submission() have a built-in local heuristic fallback. It analyzes the submission locally: word count, line count, code keywords (function, class, return) to generate a reasonable score and feedback without any AI. Zero downtime guaranteed.

AI Functions — Every Function Explained
evaluate_challenge_submission()Used by: challenges/views.py → SubmitChallengeView
  • Input: challenge_title, challenge_description, user_answer (the code/text they submitted)
  • System role: "You are an expert senior software developer and technical interviewer. Evaluate coding challenge submissions objectively and return ONLY valid JSON."
  • Returns JSON: score (0-100), overall_feedback (2-3 sentences), strengths (list), improvements (list), xp_multiplier (0.5-1.5), time_complexity (Big-O), space_complexity, complexity_table (markdown table), complexity_feedback
  • Temperature: 0.3 (low = more consistent, deterministic scoring)
  • JSON parsing: Strips markdown fences with regex, extracts {...} block, parses with json.loads()
  • Heuristic fallback: If AI fails, estimates score from word count + code keywords. Estimates complexity from loop count + binary search keywords.
generate_interview_questions()Used by: interviews/views.py → StartInterviewView
  • Input: mode (technical/hr/mixed/rapid_fire/boardroom), difficulty, topic, count (max 10), resume_context (optional Resume model)
  • Resume personalization: If user has a resume, builds context block with their skills list, project summaries (name + tech stack + description), and experience (role + company + dates). AI generates questions referencing THEIR actual work — e.g., "I see you used Django in your Nexora project. Explain how you handled WebSocket authentication."
  • Returns: List of { question, hint, expected_points } objects
  • Fallback: 40+ hardcoded questions per mode in FALLBACK_QUESTIONS dict. Randomly shuffled and drawn if AI is unavailable. Never leaves user without questions.
  • Boardroom mode: Special multi-panelist question generation with distinct voices: Tech Lead (architecture), Architect (system design), HR Manager (culture/soft skills)
evaluate_interview_answer()Used by: interviews/views.py → SubmitAnswerView
  • Input: question_text, user_answer, mode, difficulty, image_frame (base64 webcam JPEG — optional)
  • Multimodal branch: If image_frame provided → calls _call_gemini_fallback(prompt, image_frame=image_frame). Gemini Vision analyzes both the text answer AND the webcam snapshot in one call.
  • Vision analysis: Prompt explicitly asks Gemini to assess: posture (upright/slouching), eye contact (looking at camera/away), facial engagement (focused/distracted) from the image
  • Returns JSON: score (0-10), ai_feedback, eye_contact_score (0-100), posture_score (0-100), strengths, improvements, model_answer (ideal response)
  • Behavioral metrics (filler_words_count, speaking_pace/WPM) are passed from frontend to backend and stored, shown in feedback panel
generate_boardroom_debate()Used by: interviews/views.py → SubmitAnswerView (boardroom mode only)
  • Special mode simulating a real boardroom interview with 3 AI panelists, each with distinct personality and focus area
  • Tech Lead: Focuses on technical accuracy, code quality, system design decisions
  • Solutions Architect: Focuses on scalability, maintainability, trade-offs
  • HR Manager: Focuses on communication clarity, cultural fit, soft skills
  • Each panelist gives a short debate/challenge response, then a collaborative score is generated
  • Frontend reads back each panelist's response via window.speechSynthesis with different voice characteristics (rate, pitch)
generate_roadmap()Used by: roadmap/views.py → GenerateRoadmapView
  • Input: user profile data (XP, rank, recent activity, weaknesses from AI Memory), target_role (7 options)
  • Output: JSON with summary (roadmap overview) + array of week objects: { week_number, focus_area, weakness_reason, xp_goal, tasks: [{type, title, description}] }
  • Tasks are linked to actual Nexora content: challenge_id links to a real Challenge in DB, interview_mode links to an interview type
  • AI uses user's AI Memory weaknesses to prioritize focus areas: if user is weak in "System Design", roadmap includes more system design interviews
analyze_github_repo()Used by: codereview/views.py → CodeReviewCreateView
  • Step 1: Calls GitHub API /repos/{owner}/{repo}/git/trees/{branch}?recursive=1 to get full file tree
  • Step 2: Filters to code files (*.py, *.js, *.jsx, *.ts, *.tsx, *.java, *.go etc.), skips node_modules/vendor
  • Step 3: Fetches file contents via /repos/{owner}/{repo}/contents/{path} (up to N most important files)
  • Step 4: Sends all code to AI with prompt asking for JSON report: { overall_score, files: [{filename, issues: [{severity, type, description, suggestion, line_ref}]}] }
  • Severity levels: Critical (security/data loss), High (bugs/major perf), Medium (code quality), Low (style/naming)
  • Results cached in CodeReview model with aggregated counts per severity level and full report_json
generate_ats_analysis()Used by: users/views.py → ATSAnalyzeView
  • Input: Resume JSON (all 6 sections) + target_role string (e.g., "Backend Developer at Google")
  • Output JSON: ats_score (0-100), strengths (list), weaknesses (list), keyword_gaps (missing keywords for that role), checklist (dict of ATS best practices: has_email, has_github, bullet_points_used etc.), tips (actionable improvements)
  • AI reads the entire resume content to identify keyword density, section completeness, role alignment, and ATS compatibility patterns
  • Score saved to Resume.ats_score. Full report saved to Resume.audit_report JSON field for display in Resume Hub
generate_revision_guide()Used by: users/views.py → RevisionGuideView (or challenges module)
  • Input: topic string (any CS topic — "Binary Trees", "React Hooks", "System Design", "Dynamic Programming" etc.)
  • Output: Structured markdown study guide with: introduction, core concepts, examples, common pitfalls, interview tips, practice problems
  • 4-round Prep Map on frontend structures this content into: Round 1 (Learn = core concepts), Round 2 (Apply = examples), Round 3 (Reinforce = pitfalls), Round 4 (Master = interview tips)
chat_with_mentor()Used by: mentor/views.py → MentorChatView
  • Persistent conversation history: Loads all MentorMessage objects for the conversation, passes them as full chat history to Groq. AI has context of everything said in that conversation.
  • AI Memory injection: Prepends UserAIMemory.ai_summary to system prompt so mentor knows user's skill level, goals, and past performance even in a new conversation.
  • Saves both user message and AI response to MentorMessage table with role field (user/assistant)
  • Opportunity Matcher mode: Different system prompt focuses on job/internship opportunities matching user's tech stack and experience level

⚠️ Why We Use temperature=0.3 for Evaluations (NOT 0.7)

Lower temperature = more deterministic, consistent output. For scoring/evaluation (challenges, interviews), we want consistent results — same answer should get similar scores each time. For creative tasks (roadmap generation, mentor chat), we use temperature=0.7-0.9 for more varied, engaging responses.

✅ AI Memory Engine — Cross-Session Learning

The UserAIMemory model is updated after every interview completion, challenge submission, and mentor conversation. It accumulates: skills mastery levels, identified weaknesses, recurring mistake patterns, and interview performance stats. This memory is injected into EVERY subsequent AI call — creating a truly personalized AI that gets smarter about each user over time across all modules.
