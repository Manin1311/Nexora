🌐 General — Project Overview
1
What is Nexora and what problem does it solve?
General
Nexora is an all-in-one AI-powered developer growth platform. The problem: developers waste time juggling 5–8 separate tools — LeetCode for coding, Pramp for interviews, GitHub for portfolio, separate tools for resumes, mentoring, etc. There's no AI personalization or cross-platform continuity. Nexora consolidates all of this into one ecosystem with a unified XP system, persistent AI memory, and cross-module context. One platform, one profile, continuous growth.
2
What are the 10 core modules/features of Nexora?
General
  • Coding Challenges Hub — AI-evaluated challenges with Big-O analysis
  • Interview Lab — 5-mode mock interviews with webcam + speech analysis
  • Dev Mentor — Persistent AI chat mentor (Groq LLaMA 3.3 70B)
  • AI Code Review — GitHub repo health scan with severity-tagged issues
  • AI Roadmap Generator — Week-by-week career path for 7 roles
  • Peer Code Review Network — Community code review marketplace
  • Code Arena — Real-time 1v1 coding battles via WebSocket
  • Resume Hub — AI ATS scorer + full resume builder
  • Revision Hub — AI study guides with 4-round Prep Map
  • Progress & Showcase — XP/ranks, achievements, portfolio
3
What is the XP and rank system in Nexora?
General
Every user action across ALL modules earns XP: completing challenges (base XP × AI multiplier), finishing interviews, adding projects, maintaining streaks, earning achievements. XP accumulates in UserProfile.total_xp. There are 5 ranks: Explorer (0–500 XP) → Builder (501–2000) → Creator (2001–5000) → Architect (5001–15000) → Legend (15000+). The update_rank() method runs after every XP award and auto-upgrades rank + creates a notification.
4
How is Nexora deployed? What hosting is used?
General
Render Cloud — both the Django backend and PostgreSQL database are hosted on Render with auto-deploy triggered on every push to the GitHub main branch. The React frontend is built with vite build and the /dist folder is served as static files by Django via WhiteNoise middleware. The Django backend uses Gunicorn as the WSGI server and Daphne as the ASGI server for WebSocket support.

  • AI Memory Engine: AI remembers your performance across ALL modules and personalizes every interaction
  • Behavioral interview analysis: Webcam emotion/posture detection, speech filler word tracking, WPM — not just answer quality

What are the 5 interview modes and how do they differ?
General
  • Technical: Coding concepts, data structures, algorithms, system design
  • HR: Behavioral questions using STAR method, soft skills, culture fit
  • Mixed: Combination of both — technical problem-solving + behavioral reflection
  • Rapid Fire: Short, quick-answer questions testing CS fundamentals (30s per Q)

What is the AI Memory Engine and why is it important?
General
The UserAIMemory model stores a persistent learning profile per user: skills_mastery (topic → score dict), strengths, weaknesses, recurring_mistakes, interview_stats, career_goals, and activity_log. This is updated after every challenge submission, interview completion, and mentor chat. The ai_summary text field is injected into EVERY AI prompt as a system-level context — so even in a brand new conversation, the AI already "knows" this user: their skill gaps, career goals, and past performance. This creates true cross-session personalization.

Explain the 7 career tracks in the Roadmap Generator.
General
The Roadmap Generator supports: FAANG Software Engineer, Frontend Developer, Backend Developer, Full Stack Developer, DevOps Engineer, ML/AI Engineer, Product Manager (Tech). For each track, AI generates a week-by-week learning plan with tasks directly linked to Nexora's own content — e.g., a "FAANG SWE" week 3 task might say "Complete the Binary Search challenge (challenge_id=42)" or "Do a Technical interview session on System Design". The roadmap uses the user's AI Memory weaknesses to prioritize focus areas.

What is the Peer Code Review Network and how does it work?
General
A community-driven code review marketplace. Developers can submit a PeerReviewRequest with their code (as a snippet, challenge submission, or showcase project link), specify focus areas (security/performance/readability/architecture/testing), and the language. Other developers in the community browse the feed and leave PeerReviewComments with type tags (suggestion/issue/praise/question) and optional line references (e.g., "L42-L58"). Comments and requests can be upvoted. Requests have open/closed status.
10
What is the Code Arena and how do players join a battle?
General
Code Arena is a real-time 1v1 coding battle feature. Player 1 creates a room (POST /api/arena/rooms/create/) which returns a room_code. Player 2 joins via POST /api/arena/rooms/{code}/join/. Both players then connect via WebSocket (ws://…/ws/arena/{code}/?token={JWT}). When both players are connected, the server broadcasts battle_start. Players solve the same challenge in Monaco Editor. Progress updates (tests_passed) are broadcast in real-time. First to pass all tests sends battle_finish and the server declares the winner, awarding XP.
⚙️ Backend — Django & DRF
11
Why did you use Django instead of Flask or FastAPI?
Backend
Django provides a batteries-included framework with built-in ORM, admin panel, authentication, migrations, and middleware — reducing boilerplate significantly. Django REST Framework adds serializers, view classes, and permission layers on top. For a platform with 12+ models and complex relationships, Django's ORM is far more productive than Flask's bare-bones approach. FastAPI is faster for microservices but Django's monolith is easier to manage for an all-in-one platform. Also, Django Channels integrates seamlessly for WebSocket support without switching frameworks.
12
How does JWT authentication work in Nexora?
Backend
We use djangorestframework-simplejwt. Login → POST /api/auth/token/ → returns access token (expires 5 min) + refresh token (expires 7 days). Frontend stores both in localStorage. Every API request sends Authorization: Bearer <access_token> header. When access token expires, the Axios interceptor automatically calls /api/auth/token/refresh/ with the refresh token to get a new access token — user never sees a logout. JWT is stateless: no session stored in DB. Token payload contains user ID; backend verifies signature with SECRET_KEY.
13
What is a custom User model and why did you use it?
Backend
Django's default User model uses username as the login field. We replaced it with a custom model extending AbstractBaseUser + PermissionsMixin, setting USERNAME_FIELD = 'email'. This means users log in with email+password instead of username. The UserManager class defines create_user() and create_superuser(). Critical: This must be done BEFORE the first migration — changing auth models mid-project causes complex data migration issues. In settings: AUTH_USER_MODEL = 'users.User'. All ForeignKeys to the user model use settings.AUTH_USER_MODEL (not a direct import) to avoid circular imports.
14
Explain Django REST Framework serializers. Why are they important?
Backend
Serializers convert between Python objects (Django models) and JSON. They: (1) Deserialize — validate incoming JSON request data, raise validation errors, convert to Python dicts; (2) Serialize — convert model instances or querysets to JSON for the response. DRF's ModelSerializer auto-generates fields from the model definition — no need to manually map each field. Custom SerializerMethodField lets you add computed fields (e.g., is_completed based on the requesting user's submission). Without serializers, you'd manually write validation and JSON conversion for every endpoint.
15
How does Django Channels enable WebSockets? What is Daphne?
Backend
Standard Django runs on WSGI (Web Server Gateway Interface) — a synchronous protocol that handles one request at a time, with no support for persistent connections. Django Channels upgrades Django to ASGI (Asynchronous Server Gateway Interface), enabling: WebSocket connections, long-polling, background tasks. Daphne is the ASGI server that handles both HTTP and WebSocket connections. asgi.py defines routing: HTTP requests → Django's WSGI handler, WebSocket requests (path starting with /ws/) → Channels consumers. The ArenaConsumer class extends AsyncWebsocketConsumer with async/await methods.
16
What are DRF permissions? How are they used in Nexora?
Backend
DRF permissions control who can access an API view. Two main classes used: permissions.IsAuthenticated — requires valid JWT token; only logged-in users can access. permissions.AllowAny — public access (challenge list, topics). Set per view: permission_classes = [permissions.IsAuthenticated]. For example, challenge LIST is public (AllowAny) so guests can browse, but SUBMIT requires authentication. This is why unauthorized users see challenges on the landing page but get a 401 when trying to submit.
17
Explain the XP award system — how does award_xp() work?
Backend
The award_xp(user, amount, reason) function in progress/utils.py is called from every module after a user action. It: (1) Fetches UserProfile and adds XP amount; (2) Calls profile.update_rank() — compares XP against thresholds, changes dev_rank if upgraded; (3) If rank changed → creates a Notification ("You reached Builder rank!"); (4) Calls log_activity() to create UserActivity record AND update UserAIMemory.activity_log; (5) Saves profile. XP amounts are weighted: Hard challenge = 200 XP × AI multiplier (0.5–1.5 based on answer quality). Interview = based on average score.
18
What is CORS and how is it configured in Nexora?
Backend
CORS (Cross-Origin Resource Sharing) is a browser security mechanism that blocks JavaScript from making HTTP requests to a different domain/port than the current page. Since React frontend (e.g., localhost:5173) makes requests to Django API (localhost:8000), the browser blocks these by default. We use django-cors-headers package. In settings: CORS_ALLOWED_ORIGINS = ['http://localhost:5173', 'https://nexora.onrender.com']. The middleware adds Access-Control-Allow-Origin headers to every response. Without CORS configuration, the frontend would get blocked by the browser even though the server is running fine.
19
How does the GitHub repo analysis work in the Code Review module?
Backend
When user submits a GitHub URL: (1) Backend calls GitHub API /repos/{owner}/{repo}/git/trees/{branch}?recursive=1 to get full file tree; (2) Filters to source code files (.py, .js, .jsx, .ts, .java, .go, etc.), skips node_modules, vendor, __pycache__; (3) Fetches content of each important file via /repos/{owner}/{repo}/contents/{path} (base64 decoded); (4) Assembles all code into one prompt for the AI; (5) AI returns structured JSON with overall_score, and per-file issues (severity: Critical/High/Medium/Low, type, description, suggestion, line_ref); (6) Aggregated counts saved to CodeReview model, full report in report_json JSONField.
20
What is WhiteNoise and why is it used?
Backend
WhiteNoise is a Python middleware that allows Django to serve static files (CSS, JS, images) directly, without needing a separate web server like Nginx. In production on Render, we run only Gunicorn (Django). Without WhiteNoise, we'd need to configure a CDN or Nginx reverse proxy just for static files. WhiteNoise adds efficient ETag caching and gzip compression automatically. Configuration: STATICFILES_STORAGE = 'whitenoise.storage.CompressedManifestStaticFilesStorage'. Since React is built (vite build) into /frontend/dist, those files are collected by collectstatic and served by WhiteNoise too.
🎨 Frontend — React & Vite
21
Why React? Why not Angular or Vue?
Frontend
React's component-based architecture makes it easy to build complex UIs from reusable pieces. React's large ecosystem (Framer Motion, Monaco Editor, React Router) provides production-ready libraries for everything we needed. React 18's Concurrent Mode enables smoother animations and transitions. React's unidirectional data flow (state → UI) makes debugging predictable. Vite + React is the fastest development experience available. Angular is heavyweight for our use case; Vue is excellent but React has better TypeScript support and library availability for animation-heavy UIs.
22
What is React Context? How is it used for authentication?
Frontend
React Context provides a way to pass data through the component tree without prop-drilling. In AuthContext.jsx: createContext() creates the context, AuthProvider wraps the entire app and holds user, isAuthenticated, login(), logout() state. Any component anywhere in the tree calls const { user, isAuthenticated } = useAuth() to access auth state. On app load, the provider checks localStorage for a token, calls /api/users/profile/ to verify it's still valid, and populates user state. This means a page refresh keeps the user logged in without re-login.
23
How does speech-to-text work in the Interview Session? Explain the duplicate bug fix.
Frontend
We use the browser's native Web Speech API: const rec = new (window.SpeechRecognition || window.webkitSpeechRecognition)(). Set continuous=true (keeps listening) and interimResults=true (shows partial transcripts while speaking). The Bug: With both flags set, onresult fires multiple times for each word. Old code did setAnswer(prev => prev + text) — appending BOTH interim and final transcripts each time, causing "hello hello hello". The Fix: Added committedTextRef — a ref tracking only final/confirmed text. Final results are appended to the ref once. Interim results show committedText + interimPreview without modifying the ref. committedTextRef.current = '' is reset when moving to the next question.
24
What is Framer Motion and how is it used in Nexora?
Frontend
Framer Motion is a production-grade React animation library. Used throughout Nexora for: Button micro-animations: <motion.button whileHover={{ scale:1.02 }} whileTap={{ scale:0.98 }}> — every interactive button bounces subtly; Page transitions: AnimatePresence wraps routes, pages fade/slide in with initial={{ opacity:0, y:20 }} and animate={{ opacity:1, y:0 }}; Modal animations: Modals scale from 0.9→1 on open; Stagger animations: List items animate in with 50ms delay between each using staggerChildren. This creates the premium, polished feel of the UI.
25
How does the webcam snapshot work for AI body language analysis?
Frontend
On interview answer submit: (1) The live webcam stream is already attached to a <video> element via videoRef.current.srcObject = stream; (2) Create an off-screen <canvas> (320×240px); (3) Mirror the image: ctx.translate(320,0); ctx.scale(-1,1); (mirrors to match what user sees); (4) Draw video frame: ctx.drawImage(videoRef.current, 0, 0, 320, 240); (5) Convert to base64: canvas.toDataURL('image/jpeg', 0.6) (60% quality to reduce size); (6) Send as image_frame field in the API payload. Backend passes this to Gemini Vision for posture/eye-contact analysis.
26
What is the ProtectedRoute component and how does it work?
Frontend
ProtectedRoute is a wrapper component in App.jsx. It reads isAuthenticated from AuthContext. If auth is still loading → shows a spinner. If user is NOT authenticated → saves their intended URL to sessionStorage.setItem('nexora_redirect_after_login', location.pathname) → redirects to /login. If user IS authenticated → renders the children (the actual page). After login, the login page reads the saved URL from sessionStorage and redirects the user back to where they were going. This gives a smooth "login and continue" UX.
27
Why Vite over Create React App (CRA)?
Frontend
Vite is dramatically faster because it uses native ES modules in development (no bundling needed — browser loads files directly), while CRA bundles everything with Webpack on every change. Comparison: Cold start: Vite <1 second vs CRA 15–30 seconds. HMR update: Vite <100ms vs CRA 3–5 seconds. Build time: Vite 5–10s vs CRA 30–60s. Vite also has zero-config TypeScript support, better tree-shaking, and smaller build output. CRA is deprecated by the React team in favor of Vite/Next.js.
28
What is the Web Audio API and how is it used for the audio visualizer?
Frontend
The Web Audio API is a browser API for processing and visualizing audio. In the interview session: (1) const AudioCtx = new (window.AudioContext)(); (2) const analyser = AudioCtx.createAnalyser() — an audio node that performs real-time frequency analysis; (3) const source = AudioCtx.createMediaStreamSource(micStream) — connects mic stream as the audio source; (4) source.connect(analyser) — routes audio through the analyser; (5) In a requestAnimationFrame loop: analyser.getByteFrequencyData(dataArray) fills an array with frequency amplitudes; (6) These values are drawn as vertical bars on a <canvas> — creating the waveform visualizer.
🤖 AI Layer — Groq, Gemini & Prompting
29
Why Groq LLaMA 3.3 70B over OpenAI GPT-4?
AI
Speed: Groq's custom LPU (Language Processing Unit) hardware delivers 500+ tokens/sec — approximately 10x faster than OpenAI GPT-4. For real-time interview feedback, this means users get responses in 1–2 seconds vs 10–15 seconds. Cost: Groq is significantly cheaper per token. Model quality: LLaMA 3.3 70B is Meta's open-source model with strong code understanding and reasoning. No vendor lock-in: As an open-source model, it can be self-hosted if needed. The main disadvantage is Groq's rate limits on free tier — solved by our multi-key rotation system.
30
Explain the multi-key rotation and automatic failover system.
AI
In _call_groq(): (1) Reads list of Groq API keys from settings.GROQ_API_KEYS; (2) Picks a random starting index (load balancing across keys); (3) Tries each key in rotation, and for each key tries each model in GROQ_MODEL_FALLBACKS; (4) On 429 (rate limit): waits (attempt+1)*2 + random(0.5–1.5) seconds, retries up to 2 times per model; (5) If ALL Groq keys exhausted → logs "Falling back to Google Gemini" → calls _call_gemini_fallback(); (6) Gemini also has multi-key + multi-model rotation (gemini-2.5-flash → 2.0-flash → 1.5-flash → 1.5-pro); (7) If Gemini also fails → local heuristic fallback for critical functions. Result: Zero AI downtime.
31
What is multimodal AI? How does Nexora use it for interviews?
AI
Multimodal AI = models that accept multiple input types simultaneously (text + images, text + audio, etc.). In Nexora: when an interview answer is submitted with a webcam snapshot, the evaluate_interview_answer() function calls _call_gemini_fallback(prompt, image_frame=base64_jpeg). Gemini Vision receives BOTH: the text prompt (question + answer + evaluation rubric) AND the webcam image. It analyzes: posture (upright vs slouching), eye contact (looking at camera vs looking away/down), facial engagement. Returns eye_contact_score and posture_score (0-100 each). Groq/LLaMA does NOT support image input — that's why Gemini is specifically used for this feature.
32
What is prompt engineering? Give an example from Nexora.
AI
Prompt engineering is the craft of designing AI prompts to get reliable, structured, high-quality responses. Key techniques in Nexora: Role-setting system prompts: "You are an expert senior software developer" primes the AI to respond as an expert, not a general assistant. Output format specification: "Return ONLY valid JSON with this exact structure: {...}" — eliminates explanatory text we'd have to strip. Context injection: Prepending user's resume data so AI generates personalized questions. Low temperature for evaluations (0.3): More deterministic scoring. JSON mode: response_format: {"type": "json_object"} forces valid JSON output. Without careful prompting, AI might return inconsistent formats that break JSON parsing.
33
How does the AI generate resume-personalized interview questions?
AI
In StartInterviewView: after creating the session, backend tries to load the user's Resume object. If found, generate_interview_questions() builds a context block: extracts flat skills list from all skill categories, summarizes up to 3 projects (name + tech stack + description truncated to 120 chars), summarizes up to 3 experience entries (role + company + dates). This context is prepended to the prompt: "CANDIDATE PROFILE: Skills: [React, Django...], Projects: [Nexora - Django+React+AI], Experience: [Backend Dev Intern at...]". The AI then generates questions referencing this specific background — e.g., "In your Nexora project, how did you handle WebSocket authentication?"
34
What is temperature in AI models? What values does Nexora use and why?
AI
Temperature controls the randomness/creativity of AI output. Range 0–1 (or higher): 0 = completely deterministic (same input → always same output); 1 = maximum randomness/creativity. Nexora uses: 0.3 for evaluations (challenge scoring, interview answer scoring) — want consistent, objective scoring. Same answer should get similar scores each time. 0.7 for generative tasks (roadmap creation, mentor chat responses, revision guides) — want varied, engaging, creative output. 0.9 for boardroom debate — need distinct "personalities" for each AI panelist to feel different.
35
What is the ATS score and how is it calculated?
AI
ATS (Applicant Tracking System) is software used by companies to screen resumes before human review. An ATS score indicates how well a resume would pass automated screening. In Nexora, the user provides their resume JSON + a target role (e.g., "Backend Developer at Google"). AI analyzes: keyword density (does resume contain technologies relevant to that role?), section completeness (all 6 sections filled?), formatting signals (bullet points, dates, quantifiable achievements), role alignment (does experience/skills match the target role?). Returns score 0–100, keyword_gaps (missing important tech terms), checklist (has_email, has_github, uses_action_verbs), and actionable tips. Saved to Resume.ats_score in DB.
36
What is the Boardroom mode and how does multi-panelist AI work?
AI
Boardroom mode simulates a real panel interview. After the user submits an answer, generate_boardroom_debate() is called with: question, answer, full conversation history, and next question text. The AI prompt instructs it to generate responses from 3 distinct panelists: Tech Lead (challenges on technical depth, code quality), Solutions Architect (questions on scalability, system design), HR Manager (evaluates communication, cultural fit). Each panelist's response is stored in behavioral_feedback as a JSON string. On the frontend, window.speechSynthesis reads each response aloud with different voice rate/pitch settings per panelist character.
37
What is the local heuristic fallback for challenge evaluation?
AI
If BOTH Groq AND Gemini fail completely, evaluate_challenge_submission() falls back to a local algorithm: counts words and lines in the submission. Base score 60. +10 if >10 words, +10 more if >30 words, +10 more if >80 words, +5 if >3 lines (max 95). Checks for code keywords (function, class, def, const, return, import) to identify if answer contains actual code. Estimates time complexity: if two nested for-loops → O(N²), if binary/log keywords → O(log N), else O(N). Generates a generic but non-empty feedback. This ensures the platform NEVER returns an error to the user — they always get a score and feedback, even during AI outages.
38
How are filler words detected in interviews?
AI
Filler word detection happens on the frontend, not the backend. In InterviewSessionPage.jsx, each time a final speech recognition result arrives, the transcript text is scanned for a predefined list: ["um", "uh", "like", "you know", "basically", "actually", "literally", "kind of", "sort of"]. The count increments per occurrence and is displayed live as a badge counter. On answer submit, this count (filler_words_count) is sent to the backend as part of the payload, stored in InterviewQuestion.filler_words_count, and displayed in the feedback panel alongside the AI evaluation. A lower filler count improves communication score.
🗄️ Database — PostgreSQL & ORM
39
Why PostgreSQL over MySQL or SQLite?
Database
PostgreSQL's native JSONField support is the primary reason — we use JSON extensively for resume sections, AI memory, roadmap data. PostgreSQL stores and queries JSON natively with @> and ->> operators. ACID compliance — critical for XP transactions (awarding XP must be atomic; partial updates would corrupt user data). Concurrent connections — PostgreSQL handles many simultaneous connections efficiently (important for Code Arena battles). Django ORM support — best first-class Django support. SQLite is fine for development but not production (no concurrent writes). MySQL lacks some PostgreSQL features like full JSONField support and CTEs used in complex queries.
40
What are Django migrations? How do they work?
Database
Migrations are Django's version control for the database schema. When you change a model (add a field, change a field type, create a new model), you run: python manage.py makemigrations — Django detects changes and creates a migration file in app/migrations/. Then python manage.py migrate — executes the SQL changes on the database. Migrations are stored as Python files, version-controlled in Git, so the entire team applies the same schema changes. Each migration has dependencies linking to previous migrations — they run in order. You can roll back: python manage.py migrate app 0005 (go back to migration 0005).
41
What is select_related() and why is it used?
Database
select_related() is an ORM optimization that performs a SQL JOIN to fetch related objects in a single query instead of N+1 queries. Example: When listing challenges with their topics, without optimization: fetching 50 challenges + for each challenge a separate query to get its topic = 51 queries. With Challenge.objects.select_related('topic'): ONE query with a JOIN. In Nexora, used in ChallengeListView: qs = Challenge.objects.filter(is_active=True).select_related('topic'). Without this, listing 50 challenges would hit the DB 51 times. prefetch_related() is used for ManyToMany fields (challenges' tags) which can't be JOINed efficiently.
42
Why use JSONField for UserAIMemory data instead of separate tables?
Database
AI memory fields like skills_mastery, weaknesses, activity_log have dynamic, evolving structure — skills added by AI evaluations over time, variable number of weaknesses, growing activity log. Creating separate normalized tables would require: SkillsMasteryTable (user, topic, score), WeaknessTable (user, weakness_text), ActivityLogTable (user, action, timestamp) — complex JOINs to reconstruct the memory object. JSONField stores all of it in one field, fetched in one query, and the AI just reads the entire JSON object as context. Trade-off: can't run SQL filters ON these fields (e.g., WHERE skill_score > 70) — but we never need to; we always read the whole memory object.
43
What is the unique_together constraint on ChallengeSubmission?
Database
class Meta: unique_together = ('user', 'challenge') creates a composite unique constraint at the database level — meaning the combination of (user_id, challenge_id) must be unique. A user can only have ONE submission per challenge (to prevent re-scoring the same challenge for more XP). Django enforces this at the ORM level too, but the DB constraint is the ultimate safety net even against direct SQL inserts. In the view, we use get_or_create(user=request.user, challenge=challenge) which safely returns the existing submission if it exists, or creates a new one — never creating a duplicate. The status='evaluated' check before submission prevents re-evaluation.
44
What is the difference between on_delete=CASCADE and SET_NULL?
Database
on_delete defines what happens to related records when the referenced object is deleted. CASCADE: delete child records when parent is deleted. Used where child has no meaning without parent — e.g., ChallengeSubmission.user = FK(User, CASCADE): if user is deleted, all their submissions are deleted too. SET_NULL: set the FK field to NULL when referenced object is deleted. Used when child can exist independently — e.g., Challenge.topic = FK(ChallengeTopic, SET_NULL, null=True): if a topic is deleted, challenges in that topic remain but with topic=None. Also used for Certificate.challenge — certificate exists even if the source challenge is later deleted.
45
Why does AssessmentSession use UUIDField as primary key?
Database
Auto-increment integer PKs (1, 2, 3, 4…) are predictable — a malicious user could guess other users' session IDs by incrementing. For OA (Online Assessment) simulation sessions which have anti-cheat mechanisms and sensitive telemetry data, this is a security risk. UUID4 (e.g., 6ba7b810-9dad-11d1-80b4-00c04fd430c8) has 2^122 ≈ 5.3 × 10^36 possible values — practically impossible to guess. Even if someone knows a valid session exists, they can't guess another user's session ID. This is standard practice for security-sensitive resources. Regular challenge submissions and interview sessions use standard auto-increment IDs since they're all behind JWT authentication anyway.
🏗️ Architecture & Design Decisions
46
Why monolithic architecture instead of microservices?
Architecture
For a project at this scale and team size, a monolith is the right choice. Advantages: (1) Simpler deployment — one app to deploy on Render vs 10+ microservices; (2) Shared database — direct ORM joins across modules (e.g., challenge submission updating AI memory in the same transaction); (3) Lower latency — no network hops between services; (4) Easier debugging — one codebase, one stack trace; (5) Less infrastructure — no service discovery, load balancers, or API gateway needed. Microservices make sense when teams are large and modules need independent scaling. At our scale, the complexity overhead outweighs the benefits. Django's app system provides logical separation without physical distribution.
47
How does the SPA (Single Page Application) routing work with Django?
Architecture
React is a SPA — routing is handled client-side by React Router. But when a user directly visits nexora.com/challenges, the request goes to Django, which doesn't know about /challenges as a Django URL. Solution in config/urls.py: a catch-all regex route: re_path(r'^(?!api/|admin/|media/|static/).*$', serve_spa) — any URL that doesn't start with api/, admin/, media/, or static/ is served the React SPA's index.html. React Router then reads the URL in the browser and renders the correct page client-side. API routes (/api/...) are still handled by Django normally.
48
What is ASGI vs WSGI? Why does Nexora need ASGI?
Architecture
WSGI (Web Server Gateway Interface): Traditional synchronous Python web standard. Each HTTP request is handled, response sent, connection closed. Cannot maintain persistent connections — no WebSockets. ASGI (Asynchronous Server Gateway Interface): Modern async standard. Handles: HTTP requests (like WSGI), WebSocket connections (persistent, bidirectional), background tasks. Nexora NEEDS ASGI for the Code Arena — WebSocket connections must stay open for the entire battle duration (minutes). Daphne is the ASGI server that handles both: HTTP requests → Django WSGI handler, WebSocket (/ws/ paths) → Django Channels consumers. Without ASGI, real-time battles are impossible.

Why is the AI client (gemini_client.py) a centralized module instead of being split per app?
Architecture
Putting ALL AI functions in core/gemini_client.py provides: (1) Single point of change — switching AI provider (e.g., Groq → Anthropic) requires changing ONE file, not 12 app files; (2) Shared infrastructure — multi-key rotation, failover logic, and Gemini fallback are written ONCE and shared by all functions; (3) Consistent behavior — all AI calls use the same retry policy, temperature defaults, JSON parsing utilities; (4) Easier testing — mock one module to test all AI-dependent views; (5) Prevents duplication — without centralization, each app would reimplement key rotation and fallback independently. The trade-off is a large file (1770 lines) but the logical cohesion justifies it.

What are the biggest technical challenges you faced building Nexora?
Architecture
  • Speech recognition duplicates: Web Speech API's continuous + interim results caused "hello hello hello" bug. Solved with committedTextRef pattern separating final vs preview text.
  • AI rate limits: Single API key quickly exhausted during testing. Solved with multi-key rotation + Gemini fallback + local heuristics — zero downtime AI.
  • WebSocket authentication: WS handshakes can't set custom headers like HTTP. Solved by passing JWT as URL query parameter: ws://…?token={JWT}.
  • Modal background scroll: When a modal was open, background scrolled. Fixed with document.body.style.overflow = 'hidden' on modal open, restored on close.
  • Real-time battle state: Keeping two players' battle state in sync without a DB write on every progress update. Solved with in-memory ROOMS dict + channel layer broadcasts, only writing to DB on battle completion.
  • SPA routing with Django: Direct URL access to React routes returned 404. Solved with catch-all re_path serving index.html for all non-API routes.
